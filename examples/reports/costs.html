How a cost number is produced
cost = (input_tokens × input_rate) + (output_tokens × output_rate) + (cache_read_tokens × cache_rate)

# rates are resolved in this order, first hit wins:
1. local     → electricity model below (your tariff × the box's draw)
2. vendor    → official pricing page, hardcoded in pricing.py WEB_RATES
3. openrouter → live OpenRouter catalogue, cached 6h, refreshed by cron
4. unpriced  → no rate found; contributes $0 and is flagged red above
Local models — how the rate is derived
# your tariff and hardware
tariff = $0.047 / kWh
draw under load = 350 W (GPU) + 90 W (CPU, RAM, fans, PSU loss) = 440 W

# cost of one second of inference
usd_per_second = (440 / 1000) × 0.047 / 3600 = $0.000005744

# generation: one forward pass per token, so throughput sets the price
output_per_1M_tokens = usd_per_second × (1,000,000 / tokens_per_second)

# prefill: the whole prompt is processed in one batched pass, ~12x cheaper
input_per_1M_tokens = output_per_1M_tokens / 12

# cache read: no forward pass, but KV tensors still stream out of VRAM, ~60x cheaper
cache_per_1M_tokens = output_per_1M_tokens / 60

# worked example, a 30B model at 30 tok/s
output = $0.000005744 × (1,000,000 / 30) = $0.1915 per 1M output tokens
input = $0.1915 / 12          = $0.0160 per 1M input tokens
cache = $0.1915 / 60          = $0.0032 per 1M cached tokens
Local cost is electricity, shown separately from billed spend. No provider invoices a local run; the power is paid to your utility at the tariff above. The dashboard shows it as its own figure (marked elec) next to billed spend, so a local model never reads as $0 and electricity is never mistaken for an API bill. Tariff and wattage come from your config (electricity_rate_kwh, gpu_draw_watts, host_overhead_watts). Throughput per model size is measured on your own hardware; a cache read is priced at 1/60 of a generated token because it skips the forward pass but still streams the KV tensors out of VRAM with the GPU powered.
Why dashboard spend and real spend differ
Est. cost on the dashboard is what the traffic would cost at public API rates. Most of it never becomes an invoice: Anthropic and OpenCode traffic runs inside a flat-rate subscription, so their numbers measure value consumed, not money spent. Fireworks is the only genuinely pay-per-token provider configured, and local models cost electricity only. Read the totals as "what this would have cost on demand pricing".
