# P3-01 · Ruff + mypy on the package

**Phase:** 3 — Data plane  **Complexity:** 🟢 low  **Estimate:** ⏱ 3h
**Status:** not started

## Problem

The Python package has no linting and no type checking. ADR 0001 keeps Python
for the data plane; that decision only holds up if Python is held to the same
standard the frontend is getting in Phase 2.

Bugs a type checker would have caught for free, both real:

- `reports_dir` was typed as `str` but used as a `Path` (needed `.mkdir()`).
- `cli config` called `to_dict()` on an object exposing `dump()` — an
  `AttributeError` that only surfaced at runtime.

## Change

Add Ruff (lint + format) and mypy. Start non-strict, ratchet over time.

Priority order for annotations, by payoff:

1. `config.py` — the `Path`/`str` boundary that already bit.
2. The payload builders — where key names and value types must match the schema
   from P1-02.
3. Everything else.

## Acceptance

- [ ] Ruff and mypy run in CI.
- [ ] Baseline clean at the commit that adds them.
- [ ] `config.py` and the payload builders are fully annotated.
- [ ] Both are dev-only; runtime stays stdlib-only.

## Notes

Keep mypy non-strict initially. Turning on `--strict` against an unannotated
4,700-line codebase produces a wall of errors that gets suppressed wholesale,
which is worse than not running it.
