# P3-02 · Python unit tests for the collectors

**Phase:** 3 — Data plane  **Complexity:** 🟡 medium  **Estimate:** ⏱ 5h
**Status:** not started

## Problem

**CI runs zero Python tests.** It runs the leak gate and the jsdom suites; the
collectors are covered only incidentally, through the payloads they happen to
produce. The data plane — the part ADR 0001 argues is worth keeping — is the
least tested code in the repo.

## Change

Add pytest with a small committed fixture SQLite database (shared with P1-03).
Cover the shaping logic that has real consequences if wrong:

- **Cost arithmetic** — per-1M-token rates, local models priced at zero. A bug
  here misreports spend, and spend is the reason the dashboard exists.
- **`inflight()` queue counting** — counts in-flight requests per host across
  both profile databases. It replaced a bar that displayed a metric that was
  never collected; the replacement deserves a test.
- **Local-host classification** — `provOf()` and `local_host_patterns`. A
  misclassified host means self-hosted traffic is reported as billable API
  traffic. This one silently corrupts the headline number.
- **Remote-host telemetry omission** — a host that cannot report CPU/GPU must
  produce *absent* fields, never zeros. "Never invent telemetry" is a standing
  rule and should be enforced by a test, not by memory.

## Acceptance

- [ ] pytest runs in CI alongside the existing gates.
- [ ] The four areas above are covered.
- [ ] Tests use the committed fixture DB — no dependency on the author's machine
      or on any real database.
- [ ] Tests run in under 10 seconds.

## Notes

The fixture DB must contain at least two profiles, a local and a hosted
provider, and at least one unfinished session — the in-flight count reads
exactly that state, and a fixture of only completed sessions would pass while
testing nothing.
