# P6-03 · Make unpriced models impossible to miss

**Phase:** 6 — Price sheet  **Complexity:** 🟢 low  **Estimate:** ⏱ 2h
**Depends:** P6-01
**Status:** not started

## Problem

`rates_for()` returns `None` when no rate resolves, and `price_row()` then
contributes **$0** to spend. The page flags these red, but the consequence is
not stated: an unpriced model with real traffic makes total spend *silently
too low*. That is the same failure class as the payload bugs in ADR 0001 — a
plausible number that is quietly wrong.

With the catalogue fully listed (P6-01), unpriced models stop being rare and
this needs to be explicit rather than a red cell.

## Change

- A count at the top: "N models unpriced, M of them with recorded traffic".
- Unpriced **with traffic** is the actionable case — separate it from unpriced
  and unused, which is harmless.
- State the understatement in money: "spend excludes $? from N unpriced models"
  — or if that cannot be estimated, say plainly that it is unknown and
  excluded.
- Name the fix: add a `WEB_RATES` entry or an `ALIASES` mapping. There are
  currently 7 vendor overrides and 21 aliases; the reader is the person who
  can add the eighth.

## Acceptance

- [ ] Unpriced-with-traffic count is shown separately from unpriced-unused.
- [ ] The page says spend is understated when that count is > 0.
- [ ] The remedy names `WEB_RATES` / `ALIASES` specifically.
- [ ] Zero unpriced-with-traffic renders as a clean state, not an empty
      warning box.
