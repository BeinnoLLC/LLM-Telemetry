# P6-05 · Test the price sheet: it currently has zero coverage

**Phase:** 6 — Price sheet  **Complexity:** 🟡 medium  **Estimate:** ⏱ 3h
**Depends:** P6-01,P6-02
**Status:** not started

## Problem

CI renders `dashboard.html` and runs 18 jsdom suites against it. `costs.html`
is **never built in CI and never asserted**. The 237 checks say nothing about
this page. Both bugs in P6-01 and P6-02 — a 95% filtered table and a TTL
statement off by 4x — survived because nothing looks.

## Change

- Build `costs.html` in CI from the committed sample payload, as the dashboard
  already is.
- A jsdom suite asserting:
  - row count equals the resolved universe, not the traffic count
  - a known-unused model appears with rates
  - the TTL text matches the `TTL` constant
  - stale state renders its warning
  - unpriced-with-traffic count is present
- Python unit tests for `rates_for()` resolution order: local → `WEB_RATES` →
  alias → catalogue → None. That order is load-bearing and untested; the
  docstring says `WEB_RATES` must win for Codex/Astra SKUs.
- Extend the leak gate to `costs.html`. It currently only guards the dashboard,
  and this page renders model and provider names too.

## Acceptance

- [ ] CI builds `costs.html` from `examples/sample-config.json`.
- [ ] New suite runs under `tests/run-all.js` and is counted in the total.
- [ ] `rates_for()` order covered by unit tests, including the override case.
- [ ] Leak gate covers `costs.html`.
- [ ] Existing 237 checks still pass.
