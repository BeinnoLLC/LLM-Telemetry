# P6-02 · Show catalogue freshness and fix the wrong 24h claim

**Phase:** 6 — Price sheet  **Complexity:** 🟢 low  **Estimate:** ⏱ 2h
**Depends:** none
**Status:** not started

## Problem

Two defects about how current the prices are.

**1. The page states the wrong TTL.** `build_costs.py` line 287 renders:

> 3. **openrouter** → live OpenRouter catalogue, cached 24h, refreshed by cron

The actual TTL in `pricing.py` is **6 hours** (`TTL = 6 * 3600`). The page
documents its own behaviour incorrectly, on the page whose entire job is
explaining where numbers come from.

**2. Staleness is invisible.** `fetch_catalog()` has four outcomes:

```python
return models, "live"                          # fresh fetch
return ..., "cache"                            # within TTL
return ..., f"stale ({e.__class__.__name__})"  # network down, old cache
return {}, f"unavailable ({e.__class__.__name__})"
```

The source string is rendered, but with no age and no visual weight. A sheet
served from a cache that failed to refresh for a week looks identical to a
live one. For "I want the latest prices", that is the whole question.

## Change

- Fix the 24h text to read from the actual `TTL` constant, so it cannot drift
  again. Do not hardcode "6h" either — interpolate it.
- Show cache age explicitly: "fetched 2h ago" / "**stale — 3 days old**".
- `stale` and `unavailable` render as a visible warning, not muted grey text.
- `unavailable` with no cache at all must say prices are missing, not show an
  empty table that reads as "no models".

## Acceptance

- [ ] TTL text derives from the `TTL` constant; grep finds no literal "24h".
- [ ] Age in hours/days is shown next to the source.
- [ ] Stale state is visually distinct from live.
- [ ] Forcing a fetch failure with a cold cache produces a readable error.

## Notes

`fetch_catalog(force=False)` already takes a force flag. Worth exposing as
`llm-telemetry costs --refresh-prices` so the answer to "are these current"
is one command, not a wait for cron.
