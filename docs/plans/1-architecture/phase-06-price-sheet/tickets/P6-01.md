# P6-01 · List the whole catalogue, not just models with traffic

**Phase:** 6 — Price sheet  **Complexity:** 🟡 medium  **Estimate:** ⏱ 3h
**Depends:** none
**Status:** not started

## Problem

The page is a price reference, but it only shows models you have already used.
`build_costs.py` aggregates observed traffic and builds the table from that:

```python
# Aggregate observed traffic per model across every profile, so the sheet
# covers exactly the models actually in use — not a catalogue dump.
```

Measured on this box:

```
OpenRouter catalogue:            460 models
listed on the price sheet:        24 models
```

**95% of known prices are hidden.** The page cannot answer "what does Claude
Opus 4 cost per 1M tokens" unless the model has already been run — which is
backwards, and fails exactly when the answer matters: deciding whether to adopt
a model you have *not* run yet.

## Change

Render every model in the resolved price universe: the OpenRouter catalogue,
plus `WEB_RATES` vendor overrides (7), plus detected local models.

- Default sort stays most-expensive-output-first; unpriced last.
- Keep the observed-traffic columns (calls, tokens, spend) — they become
  "have I used this" annotations on a catalogue row, empty for unused models.
- A "used" flag per row, so an unused model is visibly distinct from a model
  with zero recorded calls.
- No filtering controls. Per the owner: this page does not filter.

## Acceptance

- [ ] Row count equals the resolved universe (~460+), not the traffic count.
- [ ] A model with no recorded traffic still shows its rates.
- [ ] Models with traffic keep their observed calls / tokens / spend.
- [ ] Local models still price by power draw, unchanged.
- [ ] Page states both counts: catalogue size and how many you have used.

## Notes

460 rows of static HTML is fine — no pagination, no virtual scrolling. This is
a reference sheet; Ctrl+F is the feature.
