# P9-03 · Context bloat panel: the 42x re-send is the biggest cost lever

**Phase 9 — Brand, transcript preview, and unused-signal panels** · ticket `P9-03` · complexity 🟡 medium · est ⏱ 4h · depends: -

## Why this is the highest-value addition

Measured on the live DB:

    cache_read share of all prompt tokens :  97.6%
    context re-sent per unique stored byte:  42.5x

Per-session context size per call:

    Aixiom.archive    7,017 calls   154k ctx/call
    Ahwa              5,335 calls   192k ctx/call
    Nowinv            4,979 calls   158k ctx/call
    General Config    2,704 calls   146k ctx/call

Nothing in the dashboard shows this. The Cost view shows *what* you spent; it
never shows that **97.6% of what crossed the wire was the same context sent
again**. That is the single largest controllable line item, and it is invisible.

A 192k-token context on every one of 5,335 calls is an actionable finding:
compress earlier, prune tool output, or split the session.

## Change

A panel (Cost view) answering "what is context re-sending costing me":

- Per session/project: calls, average context per call, cache_read share, and
  cost attributable to re-sent context.
- Rank by re-sent cost descending — the worst offender first.
- Sparkline of context-per-call over time: does it grow unboundedly within a
  session, or reset when compression fires?
- Threshold marker at the model's context limit, so approaching the ceiling is
  visible before it fails.

## Acceptance

- [ ] Panel ranks sessions by cost attributable to re-sent context.
- [ ] Average context per call shown per session, matching a direct SQL check.
- [ ] Cache-read share rendered as a percentage of prompt tokens.
- [ ] Sessions with few calls are excluded or flagged — a 3-call session has no
      meaningful average.
- [ ] Numbers reconcile with the Cost view totals; no third disagreeing figure.
