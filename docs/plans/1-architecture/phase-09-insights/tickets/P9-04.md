# P9-04 · Surface compression and session-end signals already in the DB

**Phase 9 — Brand, transcript preview, and unused-signal panels** · ticket `P9-04` · complexity 🟡 medium · est ⏱ 3h · depends: -

## Finding

The agent DB already records failure and pressure signals the dashboard ignores:

    compression_fallback_streak     non-null on 292 sessions
    compression_ineffective_count   non-null on 292 sessions
    compression_failure_error       non-null on   1 session
    end_reason                      non-null on 279 sessions

`end_reason` distribution:

    agent_close            245
    cron_complete           29
    (null)                  13
    startup_orphan_reap      3
    ws_orphan_reap           1
    cli_close                1

`startup_orphan_reap` and `ws_orphan_reap` mean **sessions that died without
closing cleanly** — 4 of them. The Health view tracks API success/failure but
says nothing about sessions that were killed, or about compression quietly
failing to reclaim context.

## Change

Extend the Health view with a session-lifecycle panel:

- `end_reason` breakdown, with abnormal reasons (`*_orphan_reap`, null on an
  ended session) called out rather than listed flatly.
- Compression health: sessions where `compression_ineffective_count` is rising or
  `compression_fallback_streak > 0`.
- Any `compression_failure_error` shown verbatim — it is a real error string and
  is currently visible nowhere.

## Acceptance

- [ ] `end_reason` breakdown rendered from the payload, no hardcoded list.
- [ ] Abnormal end reasons visually distinguished from clean ones.
- [ ] Compression-pressure sessions listed with their counts.
- [ ] A session with an unrecognised `end_reason` still renders (new reasons must
      not blank the panel).
- [ ] Panel hidden entirely when every session ended cleanly — no empty shell.

## Notes

`rewind_count` is 0 everywhere on this box, so it is deliberately NOT included.
Adding a panel for a column that is always zero is how dashboards accumulate
dead space.
