# P4-08 · Cost / calls / tokens weighting toggle

**Complexity:** 🟢 low  **Estimate:** ⏱ 2h  **Depends:** P4-05
**Status:** not started

## Problem

This is the ticket that decides whether the whole phase looks useful or broken.

Measured on the dev database:

- by **session count**, unattributed is 213/282 ≈ 76–84% → every chart is one
  giant grey bar and the feature looks broken
- by **estimated cost**, unattributed is $109.07/$736.81 = **15%** → the chart
  is 85% meaningful and answers the real question

Same data, same code, completely different verdict — driven only by the
weighting. So cost must be the default, and the toggle must be explicit rather
than implied.

## Change

A weighting control on the Projects view: **Cost** (default) · Calls · Tokens ·
Sessions. It drives the matrix cells (P4-05), the provider bars (P4-06) and the
trend (P4-10) together — three charts disagreeing about their unit would be
worse than no toggle.

- Persist the choice in `localStorage`, consistent with the existing theme and
  view persistence.
- Label the unit on every axis and in the panel. An unlabelled number that
  silently switches between dollars and call counts is a reporting bug.

## Acceptance

- [ ] Four modes, Cost default.
- [ ] Switching mode updates matrix, provider bars and trend in one pass.
- [ ] Axis and cell units are labelled in every mode; asserted by test.
- [ ] Choice survives reload.
- [ ] Sessions mode still renders sensibly despite the dominant Unattributed
      bucket — this is the mode that exposes the 84% problem, so it must be
      honest rather than hidden.
