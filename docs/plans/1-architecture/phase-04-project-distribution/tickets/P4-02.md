# P4-02 · Add the `project` dimension to the analytics payload

**Complexity:** 🟡 medium  **Estimate:** ⏱ 3h  **Depends:** P4-01, #23
**Status:** not started

## Problem

`collect_analytics.py` aggregates by `date model provider task ... sessions
base_url` (the `COLS` list). There is no project column, so no consumer can
group by project no matter what the UI does.

## Change

Join `sessions` in the main aggregation query and emit the resolved project key
as a new dimension, so the existing per-model/provider rows gain a `project`
field.

- The key comes from `project_of()` (P4-01). The SQL does **not** re-implement
  the stem rule — resolve in Python, or pass a resolved mapping into the query.
  Two copies of that rule will drift.
- `NULL` project stays `NULL` in the payload. Do not write the string
  `"unattributed"` into the data; that is a presentation choice and belongs in
  P4-04.
- Bump `schema_version` (from #23) — this is an additive but breaking-shaped
  change, and it is precisely the kind of payload edit that has already broken
  this project twice with a *silent empty render* rather than an error.

## Acceptance

- [ ] `analytics-data.json` rows carry `project`.
- [ ] `schema_version` is bumped and a stale payload triggers the #23 banner

- [ ] Per-project cost totals sum to the ungrouped total — assert this in a
