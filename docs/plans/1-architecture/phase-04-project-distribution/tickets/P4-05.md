# P4-05 · Projects view: project × model matrix

**Complexity:** 🟡 medium  **Estimate:** ⏱ 5h  **Depends:** P4-02
**Status:** not started

## Problem

No view answers "which models does each project actually use?". Today model mix
is global, so a project that runs entirely on a local model and one that burns
Opus are indistinguishable.

## Change

A new `Projects` view with a project × model matrix (heatmap-style table):
projects as rows, models as columns, cell = the active weighting (P4-08).

- Reuse the existing `COLORS` palette so a model keeps the same shade here as on
  every other view — the palette is already built once from all profiles for
  exactly this reason.
- Sort rows by weight descending; cap visible columns and fold the tail into
  `+N more` rather than rendering 15 unreadable columns.
- Cells are click targets → P4-07 drill-down.
- Empty cell ≠ zero cell: a project that never touched a model should read as
  blank, not as `$0.00`.

## Acceptance

- [ ] Matrix renders from the payload with no hardcoded project or model list.
- [ ] Model colours match the other views, asserted by a jsdom test against the
      shared palette.
- [ ] Row totals equal the per-project totals from the payload.
- [ ] Column totals equal the per-model totals already shown on the Usage view —
      a cross-view consistency check, which is where this kind of feature
      usually goes wrong.
- [ ] Works at 360px: the matrix scrolls horizontally with a visible affordance
      rather than overflowing (see #21).
- [ ] The existing 237 checks still pass.

## Notes

Use the fluid type/spacing tokens rather than new fixed sizes, and build on the
