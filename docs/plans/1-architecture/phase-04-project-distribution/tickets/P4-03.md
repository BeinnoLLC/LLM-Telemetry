# P4-03 · Subagent and cron sessions inherit the parent project

**Complexity:** 🟢 low  **Estimate:** ⏱ 2h  **Depends:** P4-01
**Status:** not started

## Problem

Raw attribution is 45/282 sessions (16%). A large, *recoverable* slice of the
gap is structural rather than missing: subagent sessions have no title of their
own but do know who spawned them.

Measured:

```
subagent sessions:                     24
  ... with a parent_session_id:        24   (100%)
  ... whose parent has a title:        24   (100%)
cron sessions:                         25
  ... with a title:                    25   (100%)
```

So inheritance lifts attribution from 45 → 69 sessions with **zero guesswork** —
the parent link is a fact in the database, not an inference.

## Change

In the resolver chain (P4-01), before giving up and returning `None`:

- If `parent_session_id` is set, resolve the parent's project and use it.
- Walk transitively (a subagent can spawn a subagent), with a depth cap and a
  visited-set. A self-referential or cyclic `parent_session_id` must not hang
  the collector.
- A subagent whose parent is also unattributed stays unattributed. No fallback
  invention.

## Acceptance

- [ ] All 24 subagent sessions on the dev database resolve to their parent's
      project.
- [ ] Unit test: a 3-deep subagent chain resolves to the root project.
- [ ] Unit test: a cyclic parent link terminates and returns `None` instead of
      recursing forever.
- [ ] Attribution on the dev database measurably improves from 45 to 69
      sessions; assert the direction, not the exact number, so the test does not
      rot as data grows.
- [ ] The existing 237 checks still pass.

## Notes

Cron sessions need no special handling — they already have titles, and P4-01's
stem rule is what collapses their 25 timestamped variants. Confirm that holds
after this change rather than assuming it.
