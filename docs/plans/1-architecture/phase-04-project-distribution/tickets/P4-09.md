# P4-09 · Project as a global cross-filter

**Complexity:** 🟡 medium  **Estimate:** ⏱ 3h  **Depends:** P4-05
**Status:** not started

## Problem

Once projects exist, the natural next question is "show me *everything* for this
project" — Usage, Cost, Flow, Health filtered down. Currently the only global
filters are profile and date range.

## Change

A project selector that filters the other views, sitting beside the existing
profile tabs and date range so the three read as one filter set.

- `All projects` default.
- Encode the selection in the URL hash alongside the view (`#/usage?project=…`),
  building on the hash routing in #5, so a filtered view is shareable and
  survives reload.
- When a filter is active, every affected view shows a removable chip. A silent
  global filter is how people misread a dashboard and then quote the wrong
  number in a meeting.

## Acceptance

- [ ] Selecting a project filters Usage, Cost, Flow and Health.
- [ ] Active filter is visible on every affected view, with one-click clear.
- [ ] Deep link with `project=` restores the filter.
- [ ] Filter composes with the date range and profile tabs rather than
      overriding them; asserted by test.
- [ ] A project with no rows in the current date range shows an explicit empty
      state, not a blank card.
