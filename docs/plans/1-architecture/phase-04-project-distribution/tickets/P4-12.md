# P4-12 · Per-project cost table in `costs.html` — WITHDRAWN

**Status:** withdrawn — do not implement
**GitHub:** [#49](https://github.com/BeinnoLLC/LLM-Telemetry/issues/49)
**Replaced by:** [Phase 6 — Price Sheet](../../phase-06-price-sheet/INDEX.md)

## Why it was withdrawn

This ticket proposed adding a per-project cost table, an Unattributed bucket and
a share-of-total column to `costs.html`. That was a misreading of what the page
is for.

`costs.html` is a **price sheet and debugging reference**. Its own subtitle says
so:

> Exactly how every cost number on the dashboard is produced — per-million-token
> rates, their source, and the observed spend at those rates.

It answers *"what does a token cost right now, and where did that rate come
from"*. The owner's constraint, verbatim:

> The costs.html is really meant for debugging. I want to know the latest model
> prices. so we should not do any filtering there or anything.

Everything in the withdrawn ticket was a filter or a slice — exactly what the
page must not grow. Worse, the original acceptance criterion *"table total
matches the dashboard's Projects view total"* would have created two pages
computing the same number from different code paths. Two sources for one total
is two things that can disagree, and that cross-page check would have been
permanent maintenance on a defect of my own making.

## Where the work went instead

- **Per-project spend** stays entirely in Phase 4, on the dashboard: P4-05
  (project × model matrix), P4-07 (drill-down), P4-10 (trend over time).
- **Price-sheet work** became Phase 6, aimed at the page's real purpose: list
  all ~460 catalogue models instead of only the 24 with recorded traffic
  (#59), surface catalogue freshness and fix the page's incorrect "cached 24h"
  claim — the real TTL is 6h (#60), flag unpriced models that understate spend
  (#61), open the job calculator to every model (#62), and give the page its
  first test coverage (#63).

## Standing rule this establishes

`costs.html` gets no filtering controls and no project / profile / date
dimension. It is a reference sheet; Ctrl+F is the feature. Recorded in the
Phase 6 INDEX so it constrains future tickets rather than living only in an
issue thread.

## Salvaged detail

One note from the original ticket is still true and now lives in the Phase 6
INDEX: `build_costs.py` duplicates the dashboard's `:root` theme block
(line ~171) instead of sharing tokens, so any styling added to this page must
be added twice until #28 fixes it.
