# P4-04 · Unattributed is a first-class bucket, never silently dropped

**Complexity:** 🟢 low  **Estimate:** ⏱ 2h  **Depends:** P4-02
**Status:** not started

## Problem

Even after inheritance (P4-03), most sessions have no project: 69/282 attributed
by count. Two failure modes are both unacceptable:

- **Dropping** unattributed rows — per-project totals would no longer sum to the
  real total, and the dashboard would quietly understate spend. This project has
  already shipped two "plausible but empty" renders; a plausible but *wrong*
  cost number is worse.
- **Charting it as a normal project** — by session count it is ~84% of the data
  and would dominate every bar, making the view look broken.

The saving grace, measured: unattributed sessions account for only **15% of
estimated cost** ($109.07 of $736.81). 16% of sessions carry 85% of the money.

## Change

- Render unattributed as an explicit bucket labelled *Unattributed*, visually
  distinct (muted / hatched), never hidden and never silently merged.
- Show its share as a number in the view header, e.g. "15% of spend
  unattributed", so the reader can judge how much to trust the breakdown.
- Offer a toggle to exclude it from the chart — but when excluded, the header
  must say so. An excluded bucket that leaves no trace is the drop bug wearing a
  hat.
- A tooltip explains *why* a session is unattributed (no title, no usable cwd,
  no parent) — this is the user's cue that naming a session improves the report.

## Acceptance

- [ ] Sum of all buckets including Unattributed equals the ungrouped total,
      asserted in a jsdom test.
- [ ] Unattributed share is displayed as a percentage.
- [ ] Excluding it updates the header text; asserted by test.
- [ ] Bucket is visually distinguishable from a real project without relying on
      colour alone (a11y).
