# P8-05 · Bandwidth trend and a context re-send panel

**Phase:** 8 — Bandwidth  **Complexity:** 🟡 medium  **Estimate:** ⏱ 3h
**Depends:** P8-04  **Status:** done (#72)

## Problem

A single total hides the actionable part. 97.6% of prompt tokens are re-sent
context; that ratio is the lever, and no view shows it.

## Change

A bandwidth panel: daily up/down trend, plus a **context re-send ratio**
(cache_read / (input + cache_read)) per model.

- Headline the 42x re-send factor: it explains the totals better than the GB do.
- Up:down ratio shown explicitly (currently 278:1) — it is the shape of this
  workload and worth making legible.
- Flag models whose re-send ratio is far above the fleet median: those are the
  candidates for shorter contexts or compaction.

## Acceptance

- [x] Daily trend renders from the persisted series, not recomputed at build.
- [x] Re-send ratio is shown per model and matches a hand-checked SQL query.
- [x] Panel states plainly that figures are estimates and names the method.

## Notes

This is the panel that pays for the phase: it turns "19 GB" into "your context
is re-sent 42x, here is which model does it worst".
