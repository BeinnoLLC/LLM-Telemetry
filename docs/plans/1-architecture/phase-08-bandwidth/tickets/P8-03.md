# P8-03 · Live view: per-session bandwidth, updating as work happens

**Phase:** 8 — Bandwidth  **Complexity:** 🟡 medium  **Estimate:** ⏱ 4h
**Depends:** P8-01  **Status:** not started

## Problem

The user asked to "keep tracking" bandwidth while working. The Usage tables are
historical; the Live view is the one that answers "what is this session doing to
my uplink right now".

## Change

Per-session Up/Down in the Live sessions list, plus a session-lifetime total.

- Updates on the existing 5s `pollLive()` cycle — no new timer.
- Show a rate (KB/s) alongside the cumulative figure: a rate is what makes a
  runaway session obvious.
- A session re-sending a 150k-token context every turn should visibly climb.
  That is the intended signal, not a bug.
- Subagent sessions attribute to themselves, and roll up to the parent, matching
  P4-03. Do not double-count in the total.

## Acceptance

- [ ] Each live session shows estimated Up/Down and a rate.
- [ ] Figures update on the 5s poll without a full re-render flash.
- [ ] Subagent bytes appear once in the total, not twice.
- [ ] A jsdom test drives two poll cycles and asserts the cumulative figure rises
      monotonically.

## Notes

`pollLive()` already re-renders this list every 5s; the numbers should ride that
path rather than introducing a second refresh loop.
