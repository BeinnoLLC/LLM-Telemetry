# P8-02 · Bandwidth columns in the model and provider tables

**Phase:** 8 — Bandwidth  **Complexity:** 🟡 medium  **Estimate:** ⏱ 4h
**Depends:** P8-01  **Status:** done (`ad578ea`, #71)

## Problem

The two Usage tables (`#tbl` model x provider, `#tblProv` provider rollup) report
calls and tokens but not bytes, so the largest cost of a long session — re-sending
its own history — is invisible.

## Change

Add **Up** and **Down** columns to both tables, from P8-01.

- Header must read `Up (est.)` / `Down (est.)`, not bare `Up`.
- Unit-scale per cell (KB/MB/GB); never print `19583424567 B`.
- LAN rows show their bytes with a `LAN` marker and are excluded from the
  internet total in the footer.
- Sortable by upload, because "which model is eating my uplink" is the question
  these columns exist to answer.
- Tables are already inside `.overflow-x-auto`; two more columns must not break
  the 360px case (#21).

## Acceptance

- [ ] Both tables show Up/Down, explicitly marked estimated.
- [ ] Column total equals the sum of rendered rows — asserted by a jsdom test,
      not by eye.
- [ ] LAN bytes are visible but excluded from the internet total.
- [ ] No horizontal overflow at 360px.
- [ ] A model with zero cache_read still renders a plausible non-zero upload.
