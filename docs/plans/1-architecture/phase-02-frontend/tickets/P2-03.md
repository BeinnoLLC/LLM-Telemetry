# P2-03 · dashboard.html becomes a real file

**Phase:** 2 — Presentation  **Complexity:** 🟡 medium  **Estimate:** ⏱ 4h
**Status:** not started

## Problem

The HTML shell is assembled by Python f-strings with `${...}` template segments
interleaved — 275 interpolation points. Markup and Python escaping share one
file, so neither is readable and an HTML typo is a Python string bug.

## Change

`web/dashboard.html` becomes a real HTML file with explicit, named injection
points for the payload and the built assets.

`build_dashboard.py` reduces to: read template, inject payload, write output.
Target under 150 lines of real Python.

Use an unambiguous placeholder syntax that cannot collide with JS template
literals already in the page (`${...}` is taken). A comment-delimited marker
such as `<!--INJECT:analytics-->` is safe and greppable.

## Acceptance

- [ ] `web/dashboard.html` is valid standalone HTML (opens in a browser, empty
      of data but structurally intact).
- [ ] `build_dashboard.py` is under 150 lines and contains no markup.
- [ ] Output byte-identical to today's, modulo the payload.
- [ ] Suites pass.

## Notes

The payload is injected as JSON into a script tag. Escape `</script>` in the
serialised data or a chat title containing that string will terminate the tag
early and break the page — a real hazard, since payloads carry user-authored
session titles.
