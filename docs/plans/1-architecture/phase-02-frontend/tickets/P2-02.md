# P2-02 · Extract JS into ES modules

**Phase:** 2 — Presentation  **Complexity:** 🔴 high  **Estimate:** ⏱ 8h
**Status:** not started
**Depends on:** P2-01, P2-03

## Problem

A **1,789-line JavaScript application** is stored in one Python string literal:
chart factory, force-directed graph with physics and drag, logs drawer, tab
router, colour system, Ollama panel. To every tool in the repo it is an opaque
string.

Consequences already paid:

- A colour fan emitted `hsl(-3 …)` — a negative hue — from an unwrapped
  subtraction. No linter could see it.
- A requested drag feature landed as CSS only; the handler was never written.
  Nothing failed, because nothing could fail. It went unnoticed for a session.
- Editing it means editing a string: no syntax highlighting, no jump-to-symbol,
  no refactoring tools, and Python's own escaping rules in the way.

## Change

Split into ES modules under `web/js/`, **by concern, not by line count**:

| Module | Owns |
| --- | --- |
| `palette.js` | model/tool/provider colour contract, family maps, ΔE spacing |
| `charts.js` | the `mk()` chart factory and chart-specific config |
| `flow.js` | force layout, drag, tooltip, session attribution |
| `drawer.js` | logs drawer open/close, live event rendering |
| `live.js` | live tab, Ollama panel, traffic-light bars |
| `router.js` | tab switching, help overlay, boot sequence |

Plain ES modules with `import`/`export`. **No bundler** — the clone-and-open
property is worth more than tree-shaking on a dashboard of this size.

Land it in reviewable commits, one module per commit, with the suite green at
every step. A single 1,789-line commit is unreviewable and unbisectable.

## Acceptance

- [ ] Each module is independently importable.
- [ ] No behaviour change — 237 checks green at **every** commit, not just the last.
- [ ] No circular imports.
- [ ] `build_dashboard.py` contains no JavaScript.

## Notes

Load order is a real hazard here. The existing code has at least one known
temporal-dead-zone trap (`FKIND` had to be defined before its first use) and the
flow graph must only render **after** its tab is unhidden, because it measures
element geometry — a hidden element measures zero and the layout collapses.
Module hoisting changes evaluation order; re-verify both.

Keep the single-source-of-truth rules that already exist and are easy to break
in a split: one `provOf()`, one `FKIND`, one `mk()` chart factory, one palette.
Duplicating any of them across modules reintroduces the drift they were written
to prevent.
