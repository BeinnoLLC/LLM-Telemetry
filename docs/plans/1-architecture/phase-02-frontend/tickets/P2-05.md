# P2-05 · ESLint + Stylelint in CI

**Phase:** 2 — Presentation  **Complexity:** 🟡 medium  **Estimate:** ⏱ 3h
**Status:** not started
**Depends on:** P2-01, P2-02

## Problem

There is no frontend linting, because until this phase there were no frontend
files to lint. This is the ticket that collects the payoff for the whole phase.

## Change

Add ESLint and Stylelint, running in CI. Choose rules that would have caught the
bugs this repo actually shipped — not a default preset adopted wholesale:

| Rule | Bug it would have caught |
| --- | --- |
| `no-unused-vars` | the drag handler that was never wired up |
| colour-function validation | `hsl(-3 …)` negative hue |
| `no-descending-specificity` | `cursor:pointer` silently beating `cursor:grab` |
| `no-undef` | typo'd globals in a 1,789-line scope |

Start with a config the current code can actually pass, and ratchet. A first run
that reports 400 problems gets disabled by the next person; a clean baseline
that fails on *new* problems gets kept.

## Acceptance

- [ ] ESLint and Stylelint run in CI and fail the build on error.
- [ ] Baseline is clean — zero errors at the commit that adds them.
- [ ] Both linters are dev-only; the shipped artifact gains no dependency.
- [ ] The four rules above are demonstrably active (prove with a deliberately
      broken fixture, then revert it).
