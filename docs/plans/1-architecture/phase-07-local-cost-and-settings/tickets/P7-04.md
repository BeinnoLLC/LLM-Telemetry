# P7-04 · Stop calling local models "free" in the UI

**Complexity:** 🟢 low  **Estimate:** ⏱ 2h  **Depends:** P7-01
**Status:** not started

## Problem

The word "free" is on the local-model path in several places, and it is the part
that actually misleads:

- `pricing.py` — `PROVIDER_CLASS` maps `custom`/`local`/`ollama` → `"free"`.
- `build_costs.py:285` — price sheet footnote: *"local → power model below
  (never counted as spend)"*.
- `build_costs.py:9` — docstring already admits the opposite: *"Local models are
  NOT free in reality — they burn electricity."*

A reader sees "free", concludes local inference costs nothing, and the tool has
taught them something untrue. The tool's own comments disagree with its output.

## Change

- Local rows read **"local"** or **"electricity"**, never "free".
- Local cost renders as a real figure with a marker distinguishing it from
  billed spend (e.g. `~$0.79 elec`), not as `$0` or `—`.
- The price-sheet footnote explains the power model instead of saying
  "never counted as spend".
- Keep `:free` OpenRouter tiers labelled "free tier" — those genuinely are $0
  per token, and conflating the two is the bug in reverse.

## Acceptance

- [ ] No local model is labelled "free" on either page.
- [ ] Local rows show a non-zero electricity figure, visibly distinct from
      billed cost.
- [ ] ":free" tier rows still read "free tier".
- [ ] A jsdom check asserts no local row renders the string "free".

## Notes

Cosmetic-looking, but this is the ticket that fixes the wrong belief. The
dollars in P7-01 are small; the label is what a user actually reads.
