# P7-05 · Tests for the electricity cost model

**Complexity:** 🟢 low  **Estimate:** ⏱ 2h  **Depends:** P7-01, P7-02
**Status:** not started

## Problem

`pricing.py` and `build_costs.py` have **no Python tests** (CI runs only the
jsdom suites — see #32). The $0 bug in P7-01 is exactly the kind a two-line test
catches: the power model existed, worked, and was simply never called. Nothing
failed.

## Change

Unit tests for the cost path:

- `local_rates()` returns the expected $/Mtok for a known model and tariff —
  qwen3-coder:30b at 0.047 USD/kWh, 440 W, 30 tok/s → $0.0160 in / $0.1915 out.
- `price_row()` on a local row returns **non-zero** energy cost. This is the
  regression guard for P7-01.
- A `:free` tier row still prices at $0 and is a different class from local.
- Changing `electricity_rate_kwh` changes the result proportionally (P7-02).
- An unknown model size falls back to `LOCAL_TPS_DEFAULT` rather than crashing.
- Rates are monotonic across size bands: a 70B model costs more per token than
  a 7B one.

## Acceptance

- [ ] Tests run in CI alongside the jsdom suites.
- [ ] Each test fails if its specific behaviour regresses — verified by
      temporarily breaking the code, not assumed.
- [ ] A test would have caught the original "$0 for every local row" bug.
