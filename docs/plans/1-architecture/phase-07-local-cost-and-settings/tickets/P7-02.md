# P7-02 · Tariff comes from config, not three hardcoded constants

**Complexity:** 🟢 low  **Estimate:** ⏱ 2h  **Depends:** P7-01
**Status:** not started

## Problem

`Config.electricity_rate_kwh = 0.047` exists in `config.py` and is **read
nowhere**:

```
$ grep -rn "electricity_rate_kwh" src/ tests/ examples/
src/llm_telemetry/config.py:86:    electricity_rate_kwh: float = 0.047
```

The only other hit is `PKG-INFO`, i.e. the README documents it as a real knob.
It is dead config: a user who sets it sees no change anywhere.

Meanwhile `build_costs.py` hardcodes its own copy:

```python
KWH_PRICE_USD  = 0.047   # user's tariff, USD per kWh
GPU_DRAW_W     = 350
HOST_OVERHEAD_W = 90
```

So the documented setting is ignored and the effective value is a literal in a
different module. `Config.currency` is dead in the same way.

## Change

- `electricity_rate_kwh` is actually read. Default stays **0.047 USD/kWh**.
- Add `gpu_draw_watts` (default **350**) and `host_overhead_watts`
  (default **90**) so the whole power model is configurable, not just the rate.
- `build_costs.py` reads config instead of its own constants.
- Wire `currency` too, or delete it — a field that does nothing is a trap.
- Tariff and wattage appear on the price sheet exactly as configured, so the
  page never shows a number the config contradicts.

## Acceptance

- [ ] Changing `electricity_rate_kwh` changes local costs on both pages.
- [ ] Changing either wattage changes local costs.
- [ ] No module keeps a private copy of a tariff constant.
- [ ] Defaults unchanged: 0.047 USD/kWh, 350 W GPU, 90 W host.
- [ ] `currency` is honoured or removed; nothing stays dead.
