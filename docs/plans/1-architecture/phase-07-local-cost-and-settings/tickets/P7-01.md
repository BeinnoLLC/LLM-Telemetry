# P7-01 · Local models are not free: price them from the electricity tariff

**Complexity:** 🟡 medium  **Estimate:** ⏱ 4h  **Depends:** —
**Status:** not started

## Problem

Local models are reported at **exactly $0**, and that is wrong. Measured on the
live data — 8 local models, 55.5M input / 1.17M output tokens:

| model | in | out | tok/s | electricity |
|---|---:|---:|---:|---:|
| qwen3-coder:30b | 43,408,906 | 489,030 | 30 | $0.7863 |
| qwen3.8:latest | 2,882,873 | 609,895 | 40 | $0.1221 |
| gpt-oss:20b | 6,141,741 | 31,071 | 40 | $0.0780 |
| qwen3-coder:30b (2nd profile) | 2,197,017 | 21,688 | 30 | $0.0392 |
| deepseek-r1:14b | 859,970 | 20,675 | 55 | $0.0096 |
| gpt-oss:20b (2nd profile) | 14,150 | 751 | 40 | $0.0003 |
| qwen3:14b (×2) | 1,310 | 82 | 55 | $0.0000 |

**Electricity cost of local traffic: $1.0355. Reported today: $0.00.**

The dollar figure is small; the modelling error is not. `build_costs.py` already
has the full power model — `KWH_PRICE_USD`, `GPU_DRAW_W`, `HOST_OVERHEAD_W`,
`LOCAL_TPS`, `PREFILL_SPEEDUP`, `CACHE_SPEEDUP`, and `local_rates()` that turns
them into per-Mtok rates. It works: qwen3-coder:30b prices at $0.0160/Mtok in,
$0.1915/Mtok out.

**But `pricing.py` never calls it.** In `price_row()`:

```python
elif is_local(model):
    cls = "free"
...
r = rates_for(model, catalog)   # returns None for local — see below
value = 0.0
if r: ...                        # never runs, so market_value_usd = 0.0
```

and `rates_for()` opens with:

```python
if is_local(model):
    return None
```

So the electricity model exists in one module and the cost path lives in
another, and the two were never connected. Every local row reaching the
dashboard carries `market_value_usd = 0.0`.

Worse than the missing dollars: the class is named **"free"**. `build_costs.py`
says in its own docstring *"Local models are NOT free in reality — they burn
electricity"*, and the price sheet footnote says *"never counted as spend"* —
the code contradicts its own documentation.

## Change

Move the power model into `pricing.py` (or a shared `power.py`) and make
`price_row()` use it for local rows.

- `rates_for()` returns real per-token rates for local models instead of `None`.
- Rename the class `free` → `local` end-to-end. "Free" is the actual defect:
  it is what makes a reader believe the number is zero on purpose.
- Keep the distinction that matters: local cost is **electricity, not billing**.
  `billed_usd` stays 0 (nobody invoices you); `market_value_usd` carries the
  energy cost. A separate `energy_usd` field is fine if clearer.
- `:free` OpenRouter tiers are genuinely $0/token and must stay a *different*
  class from local — do not merge them.

## Acceptance

- [ ] A local row returns non-zero energy cost from `price_row()`.
- [ ] Totals rise by ~$1.04 on the current dataset; the delta is explainable
      per model, not a lump.
- [ ] No cost class anywhere is labelled "free" for local hardware.
- [ ] `:free` tier rows still price at $0 and remain distinguishable from local.
- [ ] The power model is defined in exactly one module — `build_costs.py` stops
      keeping its own copy.
- [ ] Existing 237 checks still pass.
