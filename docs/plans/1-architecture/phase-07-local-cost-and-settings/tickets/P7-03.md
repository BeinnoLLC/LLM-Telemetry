# P7-03 · Settings page: electricity tariff and hardware, with the reasoning shown

**Complexity:** 🟡 medium  **Estimate:** ⏱ 4h  **Depends:** P7-02
**Status:** not started

## Problem

Every number describing *this user's* hardware is a Python literal. Changing a
tariff means editing source or hand-writing YAML with no feedback that it took
effect. There is no page that says what the tool assumes about your machine.

## Change

A **Settings** page reachable from the nav drawer (#3) and homepage (#2).

Fields, with the current values as defaults:

| Field | Default | Why it exists |
|---|---|---|
| Electricity rate | **0.047 USD/kWh** | Local models burn power; this converts watt-seconds into dollars. |
| GPU draw under load | **350 W** | Sustained draw of the inference box while generating. |
| Host overhead | **90 W** | CPU, RAM, fans, PSU loss during a job. |
| Currency symbol | **$** | Display only; does not convert. |

**The page must explain, not just collect.** Each field carries one line saying
what it changes. The page shows the derived figure inline:

```
(350 W + 90 W) / 1000 x $0.047 / 3600  =  $0.0000057 per second of inference
```

so a user can see their edit land. State plainly that local cost is
**electricity, not billing** — nobody invoices you for it, and it is not
comparable to an API bill without saying so.

Also surface the read-only facts the tool already derives: measured throughput
per model size band (`LOCAL_TPS`), prefill speedup (×12), cache speedup (×60),
and where each came from. A user who disagrees with a number needs to see it
first.

## Acceptance

- [ ] Settings reachable from drawer and homepage.
- [ ] Four fields render with the defaults above.
- [ ] Each field has a one-line explanation of what it affects.
- [ ] Derived $/second recomputes live as the user edits.
- [ ] Saving updates the config the collectors read — not browser-only state.
- [ ] Page states that local cost is electricity, not billing.
- [ ] Usable at 360px (#13).
