# P5-05 · A profile created after the config was written must appear

**Complexity:** 🟢 low  **Estimate:** ⏱ 2h  **Depends:** P5-02
**Status:** not started

## Problem

The end-to-end symptom of the P5-02 bug, stated as the user-visible behaviour
worth locking down with a test: create a new agent profile, rebuild, and it is
absent from the dashboard with no indication anything was missed.

## Change

- Re-run discovery on every build (it is cheap — the collectors process 2.2 GB
  in 0.36s, so there is no performance argument for caching).
- Do not cache the profile list across builds.
- A new profile appears on the next build with no config edit.
- Regression test: fixture agent home, build, add a profile directory, rebuild,
  assert the new profile is present and its rows are counted.

## Acceptance

- [ ] Regression test as described, using a temporary fixture home — never the
      developer's real `~/.hermes`.
- [ ] New profile's traffic is included in the `All` merged view, not just
      listed as a tab.
- [ ] Test asserts the profile count *changed*, so a future caching optimisation
      cannot silently reintroduce the bug.
