# P5-02 · Merge configured profiles with discovered ones instead of replacing

**Complexity:** 🟡 medium  **Estimate:** ⏱ 3h  **Depends:** P5-01
**Status:** not started

## Problem

Naming any profile in config makes every other profile on disk invisible, with
no warning. Reproduced on a box with two profiles:

```
config names 1 profile; on-disk there are 2 (default + pixelvent)
load() returned: ['Main']
-> pixelvent is INVISIBLE: True
```

So a profile created after the config was written never appears, and the
dashboard's totals silently exclude its cost and traffic. Same failure shape as
the payload bugs in Phase 1: the page looks fine and the number is wrong.

## Change

Configuration becomes a *modifier* on discovery, not a replacement:

- configured entries are used as-is (they may set a custom label, path, colour)
- discovered profiles not named in config are **appended**, not dropped
- collision on name → the config entry wins
- a new optional `"exclude": [...]` is the explicit way to leave one out

Invariant for the whole phase: **the tool never silently omits data that exists
on disk.**

## Acceptance

- [ ] A configured profile plus an unconfigured on-disk profile yields both.
- [ ] Config entry overrides the discovered entry of the same name.
- [ ] `exclude` removes a profile and that removal is reported (P5-04).
- [ ] Unit tests for merge, collision and exclude.
- [ ] The existing 237 checks still pass.
