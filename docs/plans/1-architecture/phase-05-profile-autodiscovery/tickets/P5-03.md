# P5-03 · Make the agent home configurable and environment-overridable

**Complexity:** 🟢 low  **Estimate:** ⏱ 2h  **Depends:** —
**Status:** not started

## Problem

`autodiscover_profiles(agent_home="~/.hermes")` takes a parameter, but nothing
threads a value into it — no config key, no environment variable. A non-default
agent home therefore cannot be discovered at all, and the default is baked into
the signature.

## Change

- Add an `agent_home` config key.
- Add `LLM_TELEMETRY_AGENT_HOME`, consistent with the existing
  `LLM_TELEMETRY_CONFIG` / `LLM_TELEMETRY_REPORTS` / `LLM_TELEMETRY_NO_COLLECT`
  variables.
- Precedence: env > config > `~/.hermes` default.
- Expand `~` and resolve relative paths deterministically; a missing or
  unreadable home is an explicit error naming the path tried, not an empty
  profile list.

## Acceptance

- [ ] Env var overrides config; config overrides the default.
- [ ] `~` and relative paths resolve correctly.
- [ ] A nonexistent agent home produces an error naming the path.
- [ ] Precedence covered by unit tests.
- [ ] Documented in README alongside the other env vars.
