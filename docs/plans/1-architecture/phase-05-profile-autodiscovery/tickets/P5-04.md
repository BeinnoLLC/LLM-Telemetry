# P5-04 · Report discovered, skipped and unreadable profiles in the UI

**Complexity:** 🟢 low  **Estimate:** ⏱ 2h  **Depends:** P5-02
**Status:** not started

## Problem

Profile resolution is completely silent. A profile that was excluded, had an
unreadable `state.db`, or failed to load is indistinguishable from one that
simply has no traffic — the dashboard shows the same empty-looking result either
way. That is the project's recurring failure mode.

## Change

Surface resolution in the payload and the UI:

- list what was discovered, what config added, what was excluded and why, and
  what failed to open (with the error)
- render it in the header or an info popover: "3 profiles · 1 excluded · 1
  unreadable"
- an unreadable profile is a visible warning, never a silent omission

## Acceptance

- [ ] Payload carries the resolution report (discovered / configured / excluded
      / failed, each with a reason).
- [ ] UI shows counts and exposes detail on demand.
- [ ] An unreadable `state.db` renders a warning; asserted by a jsdom test.
- [ ] Zero profiles renders an actionable empty state naming the agent home that
      was searched.
