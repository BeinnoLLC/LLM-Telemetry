# P5-01 · Config `"profiles": []` must mean none, not "discover everything"

**Complexity:** 🟢 low  **Estimate:** ⏱ 1h  **Depends:** —
**Status:** not started

## Problem

`config.py` treats an explicitly empty profile list as "unset" and falls through
to autodiscovery. Reproduced:

```
$ LLM_TELEMETRY_CONFIG=examples/sample-config.json python -c "..."
sample-config declares profiles: []
but load() returned: ['default', 'pixelvent']
```

`examples/sample-config.json` asks for **no** profiles; the loader returns the
developer's two real ones. The cause is a falsy check that cannot distinguish
"empty" from "absent".

This is not cosmetic. It is the root cause of the CI problem in P5-06: the
sample-data build reads the real `~/.hermes` instead of the committed fixtures.

## Change

Distinguish *absent* from *empty*:

- key missing → autodiscover (current behaviour, correct)
- `"profiles": []` → zero profiles, and a clear message saying the config asked
  for none
- non-empty → P5-02 semantics

Use a sentinel (`None` vs `[]`), not truthiness.
